# Git 改动分析器

## 触发条件

当用户提出以下诉求之一时启用本 skill：

- "分析当前分支改动"
- "看看这个分支改了什么"
- "生成变更摘要"
- 在 `general-test-auto` 编排流程中被调用（阶段 1）

## 执行步骤

### 1. 确定基准分支

```bash
# 获取当前分支名
git rev-parse --abbrev-ref HEAD

# 确定基准分支（优先级：用户指定 > develop > master > main）
# 如用户未指定，按以下顺序探测：
git branch -a | grep -E '(develop|master|main)$'
```

如果用户指定了基准分支，以用户为准。

### 2. 获取差异概览

```bash
# 文件变更统计
git diff <基准分支>...HEAD --stat

# 提交历史
git log <基准分支>...HEAD --oneline --no-merges

# 详细 diff（用于分析具体改动逻辑）
git diff <基准分支>...HEAD
```

### 3. 分析并分类

对每个变更文件，按照本项目（Vue 2 + SCSS 移动端）的结构进行归类，并标注单测适用性：

| 类别 | 路径特征 | 分析重点 | 单测适用性 |
|------|---------|---------|-----------|
| **页面/视图** | `src/views/` | 路由入口、页面生命周期、交互逻辑 | 仅 E2E |
| **组件** | `src/components/` | props/events 变更、复用影响面 | 可单测（组件测试） |
| **路由** | `src/router/` | 路由新增/变更、守卫逻辑 | 可单测（守卫逻辑） |
| **状态管理** | `src/store/` | Vuex state/mutation/action 变更 | 适合单测 |
| **接口层** | `src/phpApi/`, `src/javaApi/` | 接口请求参数/响应结构变更 | 可单测（mock 测试） |
| **工具函数** | `src/utils/`, `src/global/` | 公共方法变更的影响面 | 最适合单测 |
| **样式** | `*.scss`, `<style>` 块 | 布局变更、国际化 RTL 兼容 | 不适合单测 |
| **配置** | `src/constantConfig/`, `src/featureFlag/` | 功能开关、常量变更 | 不适合单测 |
| **国际化** | `src/locale/`, `src/x7lang/` | 多语言 key 新增/修改 | 不适合单测 |

### 4. 风险评估

对每个变更点评估：

- **影响范围**：仅本页面 / 跨页面 / 全局
- **风险等级**：低（样式微调）/ 中（业务逻辑改动）/ 高（公共模块/路由/状态管理改动）
- **回归建议**：列出需要回归验证的相关页面或功能入口
- **单测适用性**：根据上表标注该文件是否适合单元测试（最适合单测 / 可单测 / 仅 E2E / 不适合单测）

### 5. 读取改动文件的完整代码

对核心改动文件（风险等级中/高）：
- 使用 Read 工具读取完整文件内容
- 理解改动在业务流程中的上下文
- 识别与改动关联的组件、接口、状态

## 输出格式

输出一份 Markdown 文档（保存到 `docs/self-test/change-analysis.md`），结构如下：

```markdown
# 变更分析报告

## 基本信息
- **分支**: feature/xxx
- **基准**: develop
- **提交数**: N
- **变更文件数**: N

## 变更摘要
<!-- 一段话概括本次改动的核心目的 -->

## 变更文件清单

- 变更文件清单必须严格套用：`references/layout-file.md`

...

<!-- 以下按需展开其他类别 -->

## 影响范围与回归建议
| 功能/页面 | 是否直接改动 | 回归原因 | 优先级 | 单测适用性 |
|-----------|-------------|---------|--------|-----------|
| ... | 是/否 | ... | P0/P1/P2 | 最适合单测 / 可单测 / 仅 E2E / 不适合单测 |

## 风险点
1. ...
2. ...

## 单测适用性汇总
<!-- 供 general-test-planner 快速判断是否需要生成单元测试用例 -->
- **适合单测的文件数**: N
- **适合单测的文件列表**:
  - `src/utils/xxx.js` — 最适合单测（纯函数）
  - `src/store/modules/xxx.js` — 适合单测（Vuex mutation/action）
  - `src/components/xxx.vue` — 可单测（组件测试）
- **不适合单测的文件**: 样式/配置/国际化等 M 个文件
```

## 约束

- 路径必须是项目中真实存在的路径
- 只分析代码变更，不做推测性的需求解读
- 不确定的影响范围标注 `待确认`
