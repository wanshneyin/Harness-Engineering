# 前端注释规范 Skill

## 技能描述
本 Skill 强制 AI 在生成前端代码时遵循统一的注释规范，确保代码可读性、可维护性，并支持 JSDoc 标准文档生成。

## 触发条件
- 当用户生成任何前端代码（JS/TS/JSX/TSX/Vue）时自动触发
- 当用户输入「生成代码」「写组件」「实现功能」时自动触发
- 当用户要求「添加注释」「完善文档」时自动触发

## 核心规范

### 一、黄金法则
**注释解释 Why，而非 How**
- ❌ 坏注释：`counter++; // 将计数器加1`
- ✅ 好注释：`counter++; // 当新用户注册成功后，增加注册计数器`

### 二、JSDoc 注释规范（函数/类/复杂类型）

#### 1. 函数注释（必须）
所有函数必须包含 JSDoc 注释，包括：
- 功能描述
- `@param`：参数类型 + 名称 + 说明

**模板：**
```javascript
/**
 * 获取用户信息
 * @param {number} userId - 用户ID
 * @param {boolean} includeDetails - 是否包含详细信息
 */
async function getUser(userId, includeDetails) {
    // 实现
}
```

### 三、DOM 注释规范（Vue / HTML 模板分区标记）

#### 0. 默认策略（重要）
- **默认只使用一级与二级模块注释**（`S/E` 与 `s/e`），用于页面与子区域的清晰分区。
- **三级及以下 DOM 注释默认不使用**；只有当你明确提出“需要更细粒度分区/需要三级注释”时，才允许输出 `<!-- 模块名 -->` 这类注释。

#### 1. 标记层级与格式（必须严格一致）
- **一级 DOM 模块**：仅用于顶层模块分区（页面/区域级）
  - 开始：`<!-- S 模块名 -->`
  - 结束：`<!-- E 模块名 -->`
- **二级 DOM 模块**：仅用于一级模块内部的子模块分区（子区域级）
  - 开始：`<!-- s 模块名 -->`
  - 结束：`<!-- e 模块名 -->`
- **三级及以下 DOM**：用于更细粒度分区（组件块/列表项/细节区域等）
  - 格式：`<!-- 模块名 -->`

#### 2. 嵌套规则（强约束）
- **禁止**：一级 DOM 里面再套一级 DOM（不允许 `<!-- S ... -->` 内出现另一组 `<!-- S ... -->` / `<!-- E ... -->`）。
- **禁止**：二级 DOM 里面再套二级 DOM（不允许 `<!-- s ... -->` 内出现另一组 `<!-- s ... -->` / `<!-- e ... -->`）。
- **允许**：三级及以下 DOM 注释可在任意层级自由使用与嵌套。

#### 3. 模块名规范（建议）
- **清晰可检索**：使用与业务一致的名词短语（如「置顶区」「群列表」「空态」「快捷入口」）。
- **保持成对一致**：开始/结束的模块名必须完全一致（便于折叠与定位）。

#### 4. 示例
```vue
<template>
  <!-- S 群聊列表页 -->
  <div class="group-chat">
    <!-- s 置顶区 -->
    <div class="pinned">
      <!-- 置顶-标题 -->
      <div class="title">Pinned</div>
      <!-- 置顶-列表 -->
      <ul>
        <li v-for="item in pinnedList" :key="item.id">
          <!-- 置顶-列表项 -->
          {{ item.name }}
        </li>
      </ul>
    </div>
    <!-- e 置顶区 -->

    <!-- s 其它会话区 -->
    <div class="other">
      <!-- 其它-列表 -->
      <ul>
        <li v-for="item in otherList" :key="item.id">
          <!-- 其它-列表项 -->
          {{ item.name }}
        </li>
      </ul>
    </div>
    <!-- e 其它会话区 -->
  </div>
  <!-- E 群聊列表页 -->
</template>
```
