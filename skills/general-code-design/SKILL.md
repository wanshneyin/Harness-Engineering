# 蓝湖 MCP 工具

## 概述

通用蓝湖设计图工具，支持查看设计、样式自测。自动处理 URL 参数兼容、终端判断与尺寸转换。

## 何时使用

**只有**用户粘贴蓝湖链接（包含 `lanhuapp.com`）或明确说出蓝湖项目地址时才启用。用户仅问「蓝湖是什么」或讨论 MCP 但未提供链接时不启用。

## 通用前置工作

所有功能模块的前置条件。

### 0. MCP 服务发现

检查可用的 MCP 工具列表，找名称包含 `lanhu` 关键字的工具（如 `mcp__lanhu-mcp__lanhu_design`、`mcp__lanhu_prod__xxx` 等），提取 `<server_name>`。不可硬编码。以下文档以 `mcp__<lanhu>__` 表示。

未找到时，提示用户需要安装蓝湖 MCP 服务，确认后访问 <https://github.com/MrDgbot/lanhu-mcp> 获取最新安装指南并帮助安装。配置完成后重新触发即可。

### 1. URL 参数校验与修复

URL 必须包含 `pid` + `tid`（或 `teamId`）。缺少时提示用户按以下步骤获取正确地址：

1. 在当前蓝湖页面右上角点击「分享」按钮
2. 在浏览器打开复制的分享链接
3. 等待页面重定向后，复制最新地址

校验通过后，将 `teamId` 静默替换为 `tid`。

### 2. 终端判断与尺寸转换

按优先级确定目标宽度：

| 优先级 | 来源         | 映射                                     |
| ------ | ------------ | ---------------------------------------- |
| 1      | 用户明确指定 | PC→1920px, 移动端→375px, 或用户指定值    |
| 2      | 结构推断     | PC 典型结构→1920px, 移动端典型结构→375px |
| 3      | 无法判断     | 必须询问用户，不可自行猜测               |

**转换公式：** `转换比例 = 目标宽度 / 画布宽度（保留 4 位小数）`，`转换后值 = 原始值 × 转换比例`（四舍五入到整数，字体大小保留 1 位小数）。

所有带 `px` 单位的数值一律按比例转换。`rem` 值先转为 px（`1rem = 目标宽度 / 10`，如 375px 时 1rem = 37.5px）再按比例转换。

不转换：颜色、`font-weight`、`font-family`、百分比、`auto`、`none` 等无 `px`/`rem` 单位的属性。

## 功能模块

### 查看设计

用户要求「查看」「分析」「看看」时触发。

**流程：**

1. 通用前置工作（MCP 发现 → URL 校验修复）
2. `mcp__<lanhu>__lanhu_design`（mode=`list`）获取设计图列表，让用户确认
3. `mcp__<lanhu>__lanhu_design`（mode=`analyze`）分析选中的设计图
4. **焦点检测与范围确定：**
   - 自动检测遮罩层（`rgba(0,0,0,` + opacity < 1）+ 弹窗/抽屉/浮层 → 范围限定为弹窗，背景忽略
   - 用户明确指定（「只看弹窗」「关注表单」等）→ 按用户指定范围
   - 无遮罩且用户未指定 → 全量报告
5. 通用前置工作（终端判断与尺寸转换）
6. 输出：终端类型 + 转换比例 + 设计图类型 + **报告范围** + 关键元素（只展示转换后的值）

**设计图类型推导：** 根据 analyze 返回的 HTML 结构判断——登录/注册页、列表页、表格页、表单页、Dashboard、弹窗、空状态页、选项卡页、移动端首页、卡片组件等。如果检测到遮罩层 + 弹窗，类型推导为「弹窗/对话框」。

**数值展示规则：**

- 报告顶部「页面转换说明」集中展示画布原始宽度、目标宽度、缩放比例、`1rem` 基准。
- 后续所有表格中的 `px`/`rem` 值**只展示转换后的值**，不重复列原始值（避免冗余）。
- 字号保留 1 位小数；其他尺寸四舍五入到整数。
- 颜色/`font-weight`/`font-family`/百分比/`auto`/`none` 等无单位属性直接展示，不做转换。
- 设计图画布宽度以蓝湖返回的 layout 数据为准；若 analyze 未返回，须在「页面转换说明」中明确标注「画布宽度：未知」。

**输出格式：**

```

| 项目 | 值 |
|------|-----|
| 设计图名称 | |
| 设计图类型 | 弹窗/对话框、登录页、Dashboard… |
| 报告范围 | 仅弹窗（遮罩自动识别）/ 整个页面 / 用户指定（xxx） |
| 终端类型 | PC / 移动端 / 平板 |
| 画布原始宽度 | xxx px |

| 缩放比例 | 目标宽度 / 画布原始宽度 = x.xxxx |
| 1rem 基准（若用） | x.x px（按目标宽度） |

- 所有表格中的 px / rem 值均为转换后值；原始值与缩放比例只在「页面转换说明」中体现一次。

### 样式自测

用户要求「自测」「样式走查」「对比设计」「检查样式」时触发。

**核心目标：** 将蓝湖设计图样式规范与项目实际组件/页面样式代码对比，找出不一致。

**必须指定自测目标文件，否则提示用户提供。**

#### 核心原则

- **原则 1：一张蓝湖 = 一个状态。** 单张设计图天然不包含其他状态的 DOM。需合并多张状态图做全面自测。
- **原则 2：遮罩层 = 焦点范围。** 设计图有半透明遮罩覆盖背景时，自动限定对比范围为弹窗/抽屉及其子元素。
- **原则 3：代码中缺少设计图元素 = 结构性缺失，高亮提醒。**
- **原则 4：文本默认忽略。** 多语言/国际化文本不对比；硬编码固定文本不一致时在报告中单独提示。识别方式：`$t()`/`i18n`/props 传入/常量引用 → 动态，跳过；模板中直接写的字符串 → 固定，需对比。

#### 流程

##### 步骤 1：执行通用前置工作

MCP 发现 → URL 校验修复 → `list` 获取设计图列表 → 用户确认 → `analyze` 分析 → 终端判断与尺寸转换。

##### 步骤 2：确定自测目标文件

- **优先级 1：** 用户已指定文件路径或组件名 → 直接使用
- **优先级 2：** 从上下文推断（刚打开/编辑过的文件）→ 询问确认
- **优先级 3：** 无法确定 → 主动询问，不得跳过

##### 步骤 2.5：解析关注范围

**来源 A — 用户指定：** 识别「只看弹窗」「关注 header」「只看表单」等关键词。

**来源 B — 自动推断：** 设计图有半透明遮罩（`rgba(0,0,0,` + opacity < 1）+ 弹窗容器 → 自动限定为弹窗范围。同理处理侧边栏/抽屉、下拉/气泡浮层。

确定范围后向用户确认，无法确定时进行询问或者主动建议缩小范围，不要直接跳过或自行假设。

##### 步骤 2.6：关联校验

**校验 A — 结构匹配：** 设计图与代码重叠元素 < 2 或核心结构完全不同时，告警并询问用户是否搞错了链接或文件。允许用户强制继续。

**校验 B — 多状态检测：** 设计图列表中有 ≥ 2 张名称含相同关键词 + 不同状态标识词（默认/hover/active/disabled/loading/empty/error/success/expand/tooltip）时，列出推测状态让用户确认，逐一对比，按状态分组报告。

**校验 C — 状态完整性：** 读取代码后，检查 `v-if`/`v-show`、状态 props、`.is-loading` 等状态类、状态枚举/注释。发现代码有但设计图未覆盖的状态时提示补充，但不中断自测。

##### 步骤 3：读取并解析目标文件

提取样式代码：Vue SFC（`<style>` 块）、React（内联 style/CSS Modules/styled-components）、纯 CSS/SCSS/Less 文件。整理为属性名→值的键值对。

**Tailwind/原子 CSS：** 提取 `className` 工具类，按默认配置解析为 CSS 属性→px 值（1 单位 = 4px，颜色按默认色值 hex 映射）。自定义配置优先读取 `tailwind.config.js`。UnoCSS/WindiCSS 同理。

##### 步骤 4：提取设计规范

按关注范围过滤，含多状态提取。子组件处理：

- **项目内部组件**（`@/`/`~/`/`./`/`../` 开头）→ 读取文件，纳入对比
- **第三方组件**（element-ui/ant-design-vue/vant 等）→ 跳过内部样式，仅检查使用处覆盖样式，未检查的部分需在报告中明确列出。

**子组件风险判断：** 对纳入对比的项目内部组件，检查其被引用范围：

- 搜索该组件文件被多少文件 `import`（`grep` 组件名/路径）
- **多引用组件**（≥ 2 处引用）→ 公共组件，修改会影响其他页面
- **单引用组件**（仅 1 处引用）→ 无扩散风险

识别后列出子组件清单及风险级别向用户确认。

**对比属性（未列出的忽略）：**

| 类别 | 对比                                                                                                                                                              | 不对比                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 尺寸 | `width`、`height`、`min/max-width`、`min/max-height`、`aspect-ratio`、`box-sizing`                                                                                | —                                                                                                 |
| 间距 | `padding`、`margin`、`gap`/`row-gap`/`column-gap`                                                                                                                 | —                                                                                                 |
| 布局 | `display`、`flex-direction`、`flex-wrap`、`justify-content`、`align-items`、`align-self`、`flex`（简写）、`grid-template-columns/rows`、`grid-column`、`grid-row` | —                                                                                                 |
| 定位 | 仅当 `position: absolute/fixed/sticky` 时对比 `position`、`top`、`right`、`bottom`、`left`、`z-index`                                                             | `static`/`relative` 下的偏移                                                                      |
| 溢出 | `overflow`、`overflow-x`、`overflow-y`、`text-overflow`                                                                                                           | —                                                                                                 |
| 文本 | `font-size`、`line-height`、`font-weight`、`text-align`、`white-space`、`word-break`/`overflow-wrap`                                                              | `letter-spacing`、`font-family`、`text-transform`、文本内容（原则 4）                             |
| 颜色 | `color`、`background-color`、`opacity`                                                                                                                            | `background` 简写、渐变图像                                                                       |
| 边框 | `border`（含 `border-width`、`border-radius`、`border-color`）                                                                                                    | `outline`                                                                                         |
| 视觉 | `box-shadow`、`transform`（仅 `scale`/`rotate`/`translate` 非动效）                                                                                               | `text-shadow`、`filter`、`backdrop-filter`、`transition`、`animation`、`cursor`、`pointer-events` |

**协同说明：**

- 布局类与「结构性缺失」联动：`display: flex` 写成 `block` 视为布局结构偏差，按高风险报告
- 溢出类与步骤 5.5 联动：兜底机制识别结果直接复用，不再二次扫描
- 定位类条件化：仅在 `position: absolute/fixed/sticky` 元素上对比偏移，避免对流式元素误报
- 尺寸类 `min/max` 与 `aspect-ratio`：弹窗最大高、卡片宽高比等自适应规则需校验

##### 步骤 5：执行样式对比

按范围和状态约束逐项对比。规则：按元素/组件分组、CSS 简写拆分、1px 误差内视为匹配、颜色值统一格式。

**五种结果：**

| 结果       | 层级   | 含义                               |
| ---------- | ------ | ---------------------------------- |
| 匹配       | 属性层 | 一致                               |
| 不一致     | 属性层 | 数值不同                           |
| 样式缺失   | 属性层 | 元素存在，缺某个 CSS 属性          |
| 多余       | 属性层 | 代码有但设计未定义                 |
| 结构性缺失 | 结构层 | 设计图有该元素，代码完全找不到 DOM |

结构性缺失比样式缺失严重得多，优先报告。注意：其他状态的元素不算当前状态的结构性缺失（原则 1）。

##### 步骤 5.5：内容溢出风险扫描

在样式对比后执行，受关注范围（原则 2）和多状态约束。

**检测对象：**

| 类型 | 识别                                                                             |
| ---- | -------------------------------------------------------------------------------- |
| 文本 | `{{ }}`/`v-text`/`v-html`/JSX `{var}` + 动态来源（i18n、props、state、computed） |
| 列表 | `v-for`、`.map()`、`*ngFor`、`{#each}` 等动态渲染                                |

硬编码常量（长度 ≤ 4，如「确认」「OK」）跳过。

**容器约束判定：** 元素自身或最近祖先命中固定 `height`/`width`、`max-height < line-height × N`。`min-height`、`auto`、百分比不算约束。

**兜底机制：**

| 场景       | 命中标识                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| 单行省略   | `nowrap` + `overflow:hidden` + `text-overflow:ellipsis`、Tailwind `truncate`                                               |
| 多行省略   | `-webkit-line-clamp:N` + `-webkit-box` + `overflow:hidden`、Tailwind `line-clamp-N`                                        |
| 自适应换行 | `word-break:break-all/word` + 容器用 `min-height`                                                                          |
| 组件兜底   | `<el-tooltip>`、`<Ellipsis>` 等省略组件                                                                                    |
| 列表滚动   | `overflow:auto/scroll`、Tailwind `overflow-auto`、`<el-scrollbar>`/`<scroll-view>`/`<RecycleScroller>` 等滚动/虚拟列表组件 |
| 页面级容器 | 父级为 `<body>`/`App.vue`/`pages/**`/`views/**`/`*Page.{vue,tsx}` 根元素                                                   |

**风险分级：**

| 等级 | 文本场景                          | 列表场景                                    |
| ---- | --------------------------------- | ------------------------------------------- |
| 严重 | 固定高 + 动态文本 + 无兜底        | 固定高父容器 + 动态列表 + 无滚动 + 非页面级 |
| 高   | 固定宽 + 动态文本 + 缺 `ellipsis` | 固定高 + 仅 `overflow:hidden`（无提示裁切） |
| 中   | 多行设计仅配单行 `ellipsis`       | `max-height` 但 `overflow` 未设             |
| 低   | `max-height` 无 `overflow`        | `max-height` + `overflow:visible`           |
| 安全 | 兜底完备                          | 滚动兜底 / 虚拟列表 / 页面级 / 长度静态可控 |

**边界：**

- `position:absolute/fixed` + 固定宽高 → 等级 +1
- Flex/Grid 子项受 `align-items:stretch` 撑开时按父级再判定
- 图标/SVG 容器 → 跳过
- 蓝湖设计稿本身溢出 → 标注「设计稿即存在风险」，不归咎代码

##### 步骤 6：输出自测报告

**单状态报告结构：**

```
